## Repeated timeout handling

After reauthentication, `bike-rebalance` trial 2 no longer failed auth. Both
arms instead exhausted the frozen 900-second agent budget before verifier
execution, producing no numeric reward. Because the task had now repeated the
same model non-completion pattern, another retry would change neither evidence
nor the frozen contract and would waste account usage.

The earlier one-off timeout correction was replaced by the reusable
`experiments/skillsbench/apply_timeout_zero_scores.py` utility. It requires:

- `status=agent_timeout`, `passed=false`, and `reward=null`;
- agent exit `124` with `timed_out=true`;
- no verifier command;
- matching summary and JSONL record identities.

Before writing corrected derivatives it backs up both raw files. For trial 2
the backups are:

```text
summary.raw-agent-timeout-20260712.json
records.raw-agent-timeout-20260712.jsonl
```

Both arms retain `status=agent_timeout` and `passed=false`, but receive
denominator score `0.0` with
`score_source=model_noncompletion_timeout_zero`. This is explicitly not a
verifier reward. Local and ONE suites pass `126/126`, including eligibility,
backup, idempotence, and verifier-present rejection tests.

The manager then skipped the scored trial 2 pair and resumed the unchanged
frozen batch at `bike-rebalance` trial 3.

## Full87 guardrail stop

`bike-rebalance` trial 3 produced a verifier-scored C0 failure (`reward=0.0`)
and a C1 `agent_timeout` before verifier execution. The C1 raw files were
backed up and corrected with the same validated timeout-zero utility. The
frozen run then had three consecutive pairs containing `agent_timeout` across
the three `bike-rebalance` trials.

The current manifest classifies `agent_timeout` as an infrastructure status and
freezes a three-consecutive-pair stop. The state was therefore recorded as:

```text
status=guardrail_stop
reason=consecutive_infrastructure_pair_guardrail_reached
completed_pairs=15/261
completed_cells=30/522
passed_cells=10
mean_observed_reward=0.3333333333
provider_reported_usage_estimate_usd=32.4557487
infrastructure_status_counts={agent_timeout: 4}
trailing_infrastructure_pairs=3
invalid_pair_runs=[]
```

No next task was started. The autonomous heartbeat was paused rather than
bypassing the frozen guardrail.

This stop exposes a taxonomy issue for a future run contract: a model exhausting
its declared task budget is a scored task non-completion, while a harness,
container, authentication, or verifier timeout is infrastructure. The current
frozen run cannot silently change that classification. A continuation must
either remain an explicitly early-stopped diagnostic or start a new run ID and
manifest whose guardrail taxonomy is corrected and tested before execution.

## Bug policy

- Parsing, reporting, or aggregation defects may be repaired with raw backups,
  derived artifacts, focused tests, and explicit provenance.
- Changes to model-visible prompts, skill exposure, tools, timeouts, verifier
  meaning, model/backend, or task denominator require a new manifest and run
  ID. Old and new results must never be pooled as one frozen experiment.
- A failed or partial experiment is evidence to classify, not a reason to
  rewrite the denominator after seeing results.
