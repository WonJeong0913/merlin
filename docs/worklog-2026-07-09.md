## Harness-mode correction

User correctly pointed out that switching from free agent execution to solution
script generation changes the harness mode. The plan now treats harness mode as
a reported experimental axis, not an implementation detail:

```text
H_agentic_workspace = account-auth CLI agent runs in a host workspace, then
                      artifacts are copied into Docker for verification.
H_scripted_solver   = model generates a bounded solve script; the script runs
                      in the task Docker container; upstream verifier scores it.
H_agentic_subset    = later 5-10 task robustness run, not the main E2 path.
```

Important claim rule:

```text
Compare C0-C10 only within the same backend x model x effort x harness_mode.
Do not compare H_scripted_solver pass rate directly against upstream SkillsBench
agentic paper numbers except as a footnoted reference.
```

Next E2 implementation target:

```text
0. record wall time and account usage per run
1. deterministic task inspection inside the container
2. prompt model with task.md + C0/C1 skill context + inspection report
3. generate one solve artifact, usually solve.sh or solution.py
4. execute generated script in Docker /root
5. run verifier/test.sh
6. optional one fixed repair iteration with equal budget across C0 and C1
```

Timeouts must be separate:

```text
generation_timeout_sec
script_execution_timeout_sec, default from task frontmatter agent.timeout_sec
verifier_timeout_sec, default from verifier.timeout_sec
build_timeout_sec
```

The existing `run_model_c0_c1_pilot.py` remains useful as an
`H_agentic_workspace` robustness runner and now records `harness_mode`,
wall-time, timeout layers, and account usage when the CLI emits it. It is not
the main path for broad E2 runs.
